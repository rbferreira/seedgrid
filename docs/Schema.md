# Schema — quick reference (tables × columns)

Snapshot **faithful to the real database** (PostgreSQL 17, migrations `00001`→`00021` applied). Serves
as a quick reference so you don't need to poke the database. **Source of truth = the migrations**
(`control-plane/migrations/`); the formal and prose spec is `docs/12 - Database.md`. When adding
a migration that changes the schema, update this file in the same PR.

Conventions: PK `id uuid` (unless stated otherwise), `*_at` are `timestamptz` UTC, soft-delete via `deleted_at`.

## ⚠️ Critical gotcha — resources per Node are in `heartbeats`, NOT in `nodes`

`nodes` stores **identity/state** (hostname, status, IPs, versions, `health_score`, `bt_port`,
`disk_io_util_pct`). The **raw heartbeat resources** (disk/memory/load/cpu/uptime/versions) are
in **`heartbeats`** — **1 row per node, UPSERT by `node_id`** (the "latest" = the current row). The
"current" view exposed by the API (`GET /nodes`) is `nodes n LEFT JOIN heartbeats h ON h.node_id = n.id`.
In other words: **free disk space = `heartbeats.disk_free_bytes`** (there is no column for this in `nodes`).

## Cluster / Nodes

- **clusters**: `uuid`, `name`, `description`, `timezone`, timestamps, `deleted_at`, `deleted_by`, `operation_mode text` (global gate `full_auto`/`flex`, ADR-024; default `full_auto`). (operator manages 1 logical cluster)
- **nodes**: `cluster_id`, `uuid`, `hostname`, `display_name`, `description`, `fqdn`, `management_ip inet`, `management_port`, `agent_version`, `engine`, `engine_version`, `os_name`, `os_version`, `kernel_version`, `architecture`, `timezone`, `status`, `health_score`, `inventory_version`, `inventory_updated_at`, `registered_at`, `last_seen_at`, timestamps, `deleted_at/by`, `bt_port`, `last_ip text`, `host_uptime_seconds`, `engine_reachable bool`, `engine_started_at`, `disk_io_util_pct double` (disk busy%, saturation), `operation_mode text` (per-Node mode `sg`/`manual`, ADR-024; default `sg`; only valid under `flex` gate), `public_ipv6 text` (Node's global IPv6 address — the one opened in the firewall, ADR-034), `engine_connectable text` (`connected`/`firewalled`/`disconnected`, Engine's verdict on receiving INBOUND connections; NULL = unknown, never "closed"), `connectable_since timestamptz` (since when the current verdict is valid — this is what allows requiring *sustained firewalled* before alerting), `engine_adopted bool` (the Node joined with the qBittorrent it already ran, ADR-043: SeedGrid does not write the Engine's preferences or restart it; default `false`), `cpu_util_pct double` (CPU utilization %, sampled by the Agent via /proc/stat between heartbeats — NOT derived from load, which counts I/O wait), `incoming_peers int` (INBOUND connections open in the Agent's latest sample, `I` flag on peers; NULL = not reported = unknown, never alerts — 0 is a legitimate and distinct reading), `last_incoming_at timestamptz` (last instant when `incoming_peers` was > 0; only ADVANCES). `previous_public_ipv6 text` + `public_ipv6_changed_at timestamptz` (#147): PREVIOUS IPv6 address and when it changed — written only when the value changes from a non-empty to another non-empty (NULL→address is first boot, discovery, not rotation). Basis for the `NODE_IPV6_CHANGED` alert. ⚠️ `engine_connectable` is STICKY (libtorrent's `has_incoming_connections` never goes back to false without restarting the Engine) and therefore does not detect loss of reachability in STEADY STATE; `last_incoming_at` is the signal that DECAYS, and it is its AGE — not the value of `incoming_peers` — that triggers the `NODE_INBOUND_SILENT` alert (#155).
- **nodes.display_name** (#145): Node **nickname**, given only by SeedGrid — the OS `hostname` remains untouched and is the technical data. NULL = no nickname (the Portal displays the hostname). Written during registration with the join token (the name comes from `enroll_tokens.display_name`) and via `PUT /api/v1/nodes/{id}/display-name`. **Unique** among non-removed Nodes, case-insensitive: partial index `uk_nodes_display_name_per_cluster` on `(cluster_id, lower(display_name)) WHERE deleted_at IS NULL AND display_name IS NOT NULL` (a removed Node's name goes back to the pool). Comparing with the **hostname** of other Nodes doesn't fit in an index — it is done by the Control Plane when setting the nickname.
- **heartbeats** (1 row/node, upsert by `node_id`): `node_id`, `received_at`, `agent_version`, `engine_version`, `status`, `uptime_seconds`, `health_score`, timestamps, **`disk_total_bytes`**, **`disk_free_bytes`**, **`mem_total_bytes`**, **`mem_avail_bytes`**, **`load1 double`**, **`cpu_cores int`**.
- **health_scores**: `node_id`, `overall_score`, `cpu_score`, `memory_score`, `storage_score`, `network_score`, `temperature_score`, `engine_score`, `calculated_at`.
- **node_capabilities**: `node_id`, `capability`, `value`, `source`, `detected_at`.
- **node_credentials**: `node_id`, `token_sha256`, `state` (default `TRUSTED`), `created_at`, `last_used_at`, `revoked_at`.
- **node_labels**: `node_id`, `key`, `value`, `description`, timestamps.
- **node_tags**: `node_id`, `tag`, `source`, `created_at`.
- **enroll_tokens** (ADR-017, one-time join token): `token_sha256`, `bt_port` (reserved port), `expires_at`, `used_at`, `created_at`, `display_name text` (#145: nickname the operator chose when issuing the token; applied to the Node upon registration, NULL = no nickname).

## Torrents

- **torrents**: `uuid`, `node_id`, `hash text`, `name`, `size`, `status` (QUEUED/DOWNLOADING/SEEDING/PAUSED/CHECKING/MOVING/ERROR/ARCHIVED/DELETED/UNKNOWN), `progress`, `engine`, `magnet`, `created_by`, timestamps, `deleted_at/by`, `num_seeds`, `num_leechers` (**SWARM** — tracker scrape; this is what the Portal displays), `num_seeds_connected`, `num_leechers_connected` (actually **CONNECTED**, 00030; NULL = Agent predates the field → consumers do `COALESCE(num_seeds_connected, num_seeds)`. Basis for dead rotation: the swarm may announce ghost seeders — see `docs/25 - Business Rules.md` §3.1), `dl_speed`, `up_speed`, `size_bytes` (total size; filled by the Agent on sync **and** already on add via `.torrent` from parsing — basis for the disk check in ADR-032), `ratio`, `eta_seconds`, `downloaded_bytes`, `uploaded_bytes` (Engine **SESSION** — resets on re-add), `downloaded_total`, `uploaded_total` (**cumulative** #14 — accumulate only positive deltas between syncs; basis for aggregated ratio per Node/Cluster, see `torrent.SyncStates`), `media_info text` (mediainfo, ADR-020), `tracker_id uuid` (FK trackers, #8), `published_tracker_at`, `tracker_torrent_url`, `admission_paused_at` (admission-hold, #21 — immune to SyncStates), `prioritized_at` (manual queue prioritization, F3/00032 — jumps the admission queue; the Portal shows the torrent in yellow). `tracker_status int` + `tracker_message text` (#160): tracker verdict on announce, sampled by the Agent every 15 min (2 = working, >= 4 = rejected; NULL = **unknown**, never read as dead). The raw MESSAGE is stored instead of a derived boolean — it is what distinguishes "deleted" from "unregistered" from "invalid passkey", and grouping by it is what makes bulk cleanup possible. Partial unique `(node_id, hash) WHERE deleted_at IS NULL`. Partial index `idx_torrents_tracker_problema` covering only `tracker_status >= 4` (3 out of 983 in the 06/09/2026 measurement).
- **torrent_files** (PK `torrent_id`): `data bytea`, `byte_size`, `source` (`upload`|`engine_export`|`created`), `updated_at`. Persisted .torrent (migration/re-provisioning, ADR-018).
- **torrent_scheduler**: `torrent_id`, `selected_node`, `decision_score`, `decision_reason`, `candidates`, `algorithm_version`, `created_at`. Audit of the Scheduler's choice (1 row per add).
- **torrent_stat_samples** (PK `id bigint`): `torrent_id`, `sampled_at`, `downloaded_bytes`, `uploaded_bytes`, `dl_speed`, `up_speed`. Time series per torrent (retained for N days).
- **cluster_stat_samples** (PK `id bigint`, 00033/F2): `sampled_at`, `downloaded_total`, `uploaded_total`. Rollup of the cluster's CUMULATIVE throughput — 1 row per interval with the SUM of the cumulative totals of all torrents (includes removed ones → monotonic curve). Long retention (tunable `metrics.cluster_sample_retention`, 0=forever). Basis for the evolution chart in Metrics (`GET /metrics/cluster-throughput`, downsampling via `date_bin`). Written by the `internal/clusterstats` worker.
- **torrent_migrations** (ADR-018/031): `torrent_id`, `source_node_id`, `dest_node_id`, `status` (**QUEUED**/PENDING/COMPLETED/FAILED), `min_progress` (floor the destination must prove on recheck — snapshot of the source's progress; 1.0 = complete torrent), `token_sha256` **nullable**, `token_expires_at` **nullable**, `serve_command_id`, `pull_command_id`, `error`, timestamps, `completed_at`. **Cancellation by the operator (#87)** has no state of its own: it is `FAILED` with `error = 'cancelada pelo operador'` (the API derives `cancelled: true` from the reason) — the enum hasn't changed and there is no `CHECK`, and many readers treat "terminal" as `COMPLETED`/`FAILED`. The "in-flight" unique index covers `QUEUED` **and** `PENDING` (a torrent cannot have two migrations contending for it). The token is only issued on the QUEUED→PENDING **promotion**: generating it on queue entry would make its TTL run during the wait.

## Trackers (ADR-019/020)

- **trackers**: `user_id`, `name`, `announce text` (**secret, never exposed in the API**), `host` (display only), `is_default bool`, timestamps, `deleted_at`, `source text` (.torrent tag, e.g.: SAMARITANO), `api_url text`, `api_token text` (**secret**, UNIT3D integration), `image_host_key text` (**secret**, #193 / ADR-040, migration 00045: operator key for the tracker's own image host), `image_host_key_host text` (#193 / ADR-040: the DNS host for which the key was registered — if the profile's `upload_url` changes host, the old key is no longer valid). Unique name per operator among active ones; ≤1 default per operator.
- **tracker_profiles** (ADR-037, 00043): the **site** profile of a tracker — layer 2, exportable, **without a credential column** (layer 3, `api_token`/`announce`, lives in `trackers` and is never exported). `tracker_id` (FK trackers; **one active profile per tracker**, partial unique `WHERE deleted_at IS NULL`), `family text` (default `unit3d`, validated in Go), `schema_version int` (≥ 1; version of the profile **format**, which the #197 export stamps — the version the code emits — and the import checks), `taxonomy jsonb` (always an object, `CHECK`), `created_at`, `updated_at`, `deleted_at`. `taxonomy` is the profile **document** — despite the column's historical name: the axes at the root, `{"category"|"type"|"resolution": [{"id", "name", "kind"?, "origin"}]}`, and a reserved key per section alongside them. The `description` section (#192, **no migration and no new column**) is the key `"description": {"media_blocks": […], "game_blocks": […], "media_info_tag": "mediainfo"}` — the composition of the upload description (which blocks, in what order, which tag wraps the MediaInfo); absent = the default, and the row prior to #192 is, byte for byte, a document without the section. The `image_host` section (#193, ADR-040, **no migration and no new column**) is the key `"image_host": {"name", "upload_url", "file_field", "auth_header", "auth_prefix", "url_path", "thumbnail_path"?}` — the closed-form Spec of the tracker's own image host for the screenshot upload chain; absent = no own host (only the global imgbb in the chain), and the row prior to #193 is, byte for byte, a document without the section. In terms of axes: `origin` `seed` (migration) | `discovered` (discovered in the site catalog, #196) | `manual` (operator) | `imported` (profile file, #197; no migration — lives in JSONB) — discovery and import **never overwrite `manual`** (import also does not rename `discovered` without being asked; unknown origin is protected), and the origin is local state that **does not travel** in the exchange file; `kind` (`movie`/`tv`/`game`, only in `category`) is the role the Portal uses for season/episode and game search. Row created on demand; tracker without a row = empty profile. Writes serialized by `FOR UPDATE`. 00043 seeds the already registered samaritano profile with the taxonomy that was hardcoded in the Portal. JSONB (and not one row per term) because the export/validation unit is the document and new axes/sections are added without a migration — see `docs/12 - Database.md` §52-A.

## Commands / Events / Alerts

- **commands** (durable queue, Agent polling, ADR-014): `node_id`, `type`, `payload jsonb`, `status` (PENDING/DISPATCHED/DONE/FAILED), `result jsonb`, `error`, `retry_count` (deliveries to the Agent — the Claim re-delivers orphaned DISPATCHED after `commands.redispatch_after` and marks FAILED when `commands.max_attempts` is exceeded, #111), `created_by`, `created_at`, `dispatched_at`, `finished_at`. `seq` (identity) is the **queue entry order**: the Claim selects and returns by it — `created_at` ties within a transaction and cannot be used for ordering (#28).
- **events**: `event_type_id`, `node_id`, `torrent_id`, `user_id`, `message`, `payload jsonb`, `severity`, `created_at`.
- **event_types**: `code`, `name`, `severity` (default INFO), `description`, `created_at`.
- **activities** (ADR-022, orchestration feed — SEPARATE track from events/alerts): `kind` (admission_hold/admission_resume/scheduled/downloading/seeding), `torrent_id`, `torrent_name` (denormalized), `node_id`, `message`, `detail jsonb` (the "why"), `created_at`. Append-only.
- **audit_log** (ADR-025, operator action audit — SEPARATE track from events/activities/alerts): `actor` (username), `action` (PT-BR friendly description, e.g.: `Alterou a configuração «Node offline após» para 120s`), `method`, `path`, `status_code`, `source_ip`, `created_at`. Append-only; recorded by middleware on mutating protected routes + login; handlers enrich `action` via `httpx.SetAuditAction`.
> **Retention (#112):** `commands` (terminal), `events`, `activities`, `audit_log` and expired `sessions` are pruned by the maintenance worker according to the `retention.*` / `workers.maintenance_interval` tunables (0 disables it). Samples (`torrent_stat_samples`/`cluster_stat_samples`) already had their own pruning. ⚠️ **Command referenced by `torrent_migrations` (`serve_command_id`/`pull_command_id`) is never pruned (#213):** the FKs do not have `ON DELETE`, and a single such command in the batch would crash the entire `DELETE` — `commands` pruning had never run in production (64 migration commands blocking 53.732). `ON DELETE SET NULL` was discarded because `IS NOT NULL` on these columns determines the cleanup of a failed migration (`resumeSource`/`discardDestCopy`) and `Reconcile` does a `JOIN` on the pull.

- **alerts** (ADR-008): `code`, `severity` (default WARNING), `status` (default OPEN), `node_id`, `message`, `payload jsonb`, `opened_at`, `resolved_at`, timestamps. `episode_key text` (#211): identity of the condition that opened the alert — the IPv6 rotation, the start of the input silence, the Engine verdict —, formatted in UTC with microseconds; an episode that has already generated an alert, in any status, does not reopen. NULL = rule without an episode (dedup only by OPEN). `expired bool` (default false, #211): closed due to **validity** (`alerting.reachability_ttl`), not because the condition ceased to exist.

## Authentication / RBAC

- **users**: `uuid`, `username citext` (unique, case-insensitive), `display_name`, `email citext`, `password_hash`, `status` (default ACTIVE), `last_login_at`, timestamps, `deleted_at/by`.
- **roles**: `name`, `description`, `system bool`, timestamps.
- **permissions**: `resource`, `action`, `description`, `created_at`.
- **role_permissions** (composite PK): `role_id`, `permission_id`, `created_at`.
- **user_roles** (composite PK): `user_id`, `role_id`, `created_at`.
- **sessions**: `user_id`, `session_token`, `ip_address inet`, `user_agent`, `expires_at`, `last_activity`, `created_at`.

## Configuration

- **settings** (ADR-023, dynamic tunables with hot-reload): `key` (PK, namespaced, e.g.: `admission.dead_grace`), `value` (string; parsed by catalog type), `updated_at`, `updated_by` (`env-seed` on boot seed). Pure KV — the metadata (type/default/description/limits) lives in the **code catalog** (`internal/settings/catalog.go`), not in the database. Default override; removing the row = reset to default. See `25 - Business Rules.md`.
- **node_settings** (ADR-039, #144 — PER NODE override of Agent/Engine behavior configuration): `id` (UUID PK), `node_id` (FK → `nodes`, `ON DELETE CASCADE`), `key` (namespaced key from the catalog, only the `PerNode` ones: `agent.heartbeat_interval`, `agent.command_poll_interval`, `agent.log_level`, `engine.*`), `value` (string; parsed by catalog type), `created_at`, `updated_at`, `updated_by` (operator; `semeadura (env do Node)` when it comes from seeding, §7 of the ADR). `UNIQUE (node_id, key)`. Same logic as `settings`: the metadata lives in the code catalog and the value is validated by the **same `Spec`**; removing the row = the Node reverts to the cluster value (the `settings`). **No soft delete** on purpose, just like `settings`: the history of who changed what (before and after) is kept in **Audit** (ADR-025), not in a dead row here; Nodes are soft-deleted and the override of a removed Node simply stops being read. Effective precedence: **Node override > cluster value (`settings`/catalog default) > Node env > code default** — the last two steps belong to the Agent.
- **nodes (Agent config, ADR-039)**: `agent_config_version text` (the `version` of the configuration that the Agent successfully applied, returned in the heartbeat; NULL = the Agent has never reported — prior to ADR-039 — and is **never** read as "up to date"), `agent_config_applied_at timestamptz` (when this version was first reported; only changes when the version changes), `agent_config_seeded_at timestamptz` (the "once per Node" seeding of overrides from the `.env` reported by the Agent — once populated, the Control Plane stops seeding, even if the operator deletes the seeded override).
