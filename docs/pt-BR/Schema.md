# Schema — referência rápida (tabelas × colunas)

Snapshot **fiel do banco real** (PostgreSQL 17, migrations `00001`→`00021` aplicadas). Serve
de consulta rápida pra não precisar cutucar o banco. **Fonte da verdade = as migrations**
(`control-plane/migrations/`); a spec formal e prosada é `docs/12 - Database.md`. Ao adicionar
uma migration que mude schema, atualize este arquivo na mesma entrega.

Convenções: PK `id uuid` (salvo dito), `*_at` são `timestamptz` UTC, soft-delete via `deleted_at`.

## ⚠️ Gotcha crítico — recursos por Node ficam em `heartbeats`, NÃO em `nodes`

`nodes` guarda **identidade/estado** (hostname, status, IPs, versões, `health_score`, `bt_port`,
`disk_io_util_pct`). Os **recursos crus do heartbeat** (disco/memória/load/cpu/uptime/versões) ficam
em **`heartbeats`** — **1 linha por node, UPSERT por `node_id`** (o "último" = a linha corrente). A
visão "atual" que a API expõe (`GET /nodes`) é `nodes n LEFT JOIN heartbeats h ON h.node_id = n.id`.
Ou seja: **espaço livre de disco = `heartbeats.disk_free_bytes`** (não existe coluna disso em `nodes`).

## Cluster / Nodes

- **clusters**: `uuid`, `name`, `description`, `timezone`, timestamps, `deleted_at`, `deleted_by`, `operation_mode text` (gate global `full_auto`/`flex`, ADR-024; default `full_auto`). (operador administra 1 cluster lógico)
- **nodes**: `cluster_id`, `uuid`, `hostname`, `display_name`, `description`, `fqdn`, `management_ip inet`, `management_port`, `agent_version`, `engine`, `engine_version`, `os_name`, `os_version`, `kernel_version`, `architecture`, `timezone`, `status`, `health_score`, `inventory_version`, `inventory_updated_at`, `registered_at`, `last_seen_at`, timestamps, `deleted_at/by`, `bt_port`, `last_ip text`, `host_uptime_seconds`, `engine_reachable bool`, `engine_started_at`, `disk_io_util_pct double` (busy% do disco, saturação), `operation_mode text` (modo por-Node `sg`/`manual`, ADR-024; default `sg`; só vale sob gate `flex`), `public_ipv6 text` (endereço IPv6 global do Node — o que se libera no firewall, ADR-034), `engine_connectable text` (`connected`/`firewalled`/`disconnected`, veredito do Engine sobre receber conexão de ENTRADA; NULL = desconhecido, nunca "fechado"), `connectable_since timestamptz` (desde quando o veredito atual vale — é o que permite exigir *firewalled sustentado* antes de alertar), `engine_adopted bool` (o Node entrou com o qBittorrent que já rodava, ADR-043: começa em Manual e os overrides dele são semeados a partir desse Engine; depois é gerenciado como qualquer Node; padrão `false`), `machine_id text` (o `/etc/machine-id` lido pelo Agent, ADR-044; NULL antes da `00049`. O hostname é único só entre Nodes **ativos** — índice parcial `uk_nodes_hostname_per_cluster`), `cpu_util_pct double` (utilização de CPU %, amostrada pelo Agent via /proc/stat entre heartbeats — NÃO derivada do load, que conta espera de I/O), `incoming_peers int` (conexões de ENTRADA abertas na última amostra do Agent, flag `I` nos peers; NULL = não reportado = desconhecido, nunca alerta — 0 é leitura legítima e distinta), `last_incoming_at timestamptz` (último instante em que `incoming_peers` foi > 0; só AVANÇA). `previous_public_ipv6 text` + `public_ipv6_changed_at timestamptz` (#147): endereço IPv6 ANTERIOR e quando trocou — escritos só quando o valor muda de um não-vazio para outro não-vazio (NULL→endereço é primeiro boot, descoberta, não rotação). Base do alerta `NODE_IPV6_CHANGED`. ⚠️ `engine_connectable` é GRUDENTO (`has_incoming_connections` do libtorrent nunca volta a falso sem reiniciar o Engine) e por isso não detecta perda de alcançabilidade em REGIME; `last_incoming_at` é o sinal que DECAI, e é a IDADE dele — não o valor de `incoming_peers` — que vira o alerta `NODE_INBOUND_SILENT` (#155).
- **nodes.display_name** (#145): **apelido** do Node, dado só do SeedGrid — o `hostname` do SO fica intocado e é o dado técnico. NULL = sem apelido (o Portal exibe o hostname). Escrito pelo registro com join token (o nome vem de `enroll_tokens.display_name`) e por `PUT /api/v1/nodes/{id}/display-name`. **Único** entre Nodes não removidos, sem diferenciar maiúsculas: índice parcial `uk_nodes_display_name_per_cluster` sobre `(cluster_id, lower(display_name)) WHERE deleted_at IS NULL AND display_name IS NOT NULL` (o nome de um Node removido volta ao pool). A comparação com o **hostname** dos outros Nodes não cabe num índice — é feita pelo Control Plane ao definir o apelido.
- **heartbeats** (1 linha/node, upsert por `node_id`): `node_id`, `received_at`, `agent_version`, `engine_version`, `status`, `uptime_seconds`, `health_score`, timestamps, **`disk_total_bytes`**, **`disk_free_bytes`**, **`mem_total_bytes`**, **`mem_avail_bytes`**, **`load1 double`**, **`cpu_cores int`**.
- **health_scores**: `node_id`, `overall_score`, `cpu_score`, `memory_score`, `storage_score`, `network_score`, `temperature_score`, `engine_score`, `calculated_at`.
- **node_capabilities**: `node_id`, `capability`, `value`, `source`, `detected_at`.
- **node_credentials**: `node_id`, `token_sha256`, `state` (default `TRUSTED`), `created_at`, `last_used_at`, `revoked_at`.
- **node_labels**: `node_id`, `key`, `value`, `description`, timestamps.
- **node_tags**: `node_id`, `tag`, `source`, `created_at`.
- **enroll_tokens** (ADR-017, join token one-time): `token_sha256`, `bt_port` (porta reservada), `expires_at`, `used_at`, `created_at`, `display_name text` (#145: apelido que o operador escolheu ao emitir o token; aplicado ao Node no registro, NULL = sem apelido).

## Torrents

- **torrents**: `uuid`, `node_id`, `hash text`, `name`, `size`, `status` (QUEUED/DOWNLOADING/SEEDING/PAUSED/CHECKING/MOVING/ERROR/ARCHIVED/DELETED/UNKNOWN), `progress`, `engine`, `magnet`, `created_by`, timestamps, `deleted_at/by`, `num_seeds`, `num_leechers` (**SWARM** — scrape do tracker; é o que o Portal exibe), `num_seeds_connected`, `num_leechers_connected` (**CONECTADOS** de fato, 00030; NULL = Agent anterior ao campo → quem consome faz `COALESCE(num_seeds_connected, num_seeds)`. Base da rotação por morto: o swarm pode anunciar seeder fantasma — ver `docs/25 - Business Rules.md` §3.1), `dl_speed`, `up_speed`, `size_bytes` (tamanho total; preenchido pelo Agent no sync **e** já no add via `.torrent` a partir do parse — base do check de disco da ADR-032), `ratio`, `eta_seconds`, `downloaded_bytes`, `uploaded_bytes` (SESSÃO do Engine — zera no re-add), `downloaded_total`, `uploaded_total` (**cumulativos** #14 — acumulam só deltas positivos entre syncs; base do ratio agregado por Node/Cluster, ver `torrent.SyncStates`), `media_info text` (mediainfo, ADR-020), `tracker_id uuid` (FK trackers, #8), `published_tracker_at`, `tracker_torrent_url`, `admission_paused_at` (admission-hold, #21 — imune ao SyncStates), `prioritized_at` (priorização manual na fila, F3/00032 — fura a fila de admissão; o Portal mostra o torrent em amarelo). `tracker_status int` + `tracker_message text` (#160): veredito do tracker no announce, amostrado pelo Agent a cada 15 min (2 = funcionando, >= 4 = recusado; NULL = **desconhecido**, nunca lido como morto). A MENSAGEM crua é guardada em vez de um booleano derivado — é ela que distingue "apagado" de "não registrado" de "passkey inválida", e agrupar por ela é o que torna a limpeza em lote possível. Único parcial `(node_id, hash) WHERE deleted_at IS NULL`. Índice parcial `idx_torrents_tracker_problema` cobrindo só `tracker_status >= 4` (3 em 983 na medição de 06/09/2026).
- **torrent_files** (PK `torrent_id`): `data bytea`, `byte_size`, `source` (`upload`|`engine_export`|`created`), `updated_at`. .torrent persistido (migração/re-provisão, ADR-018).
- **torrent_scheduler**: `torrent_id`, `selected_node`, `decision_score`, `decision_reason`, `candidates`, `algorithm_version`, `created_at`. Auditoria da escolha do Scheduler (1 linha por add).
- **torrent_stat_samples** (PK `id bigint`): `torrent_id`, `sampled_at`, `downloaded_bytes`, `uploaded_bytes`, `dl_speed`, `up_speed`. Série temporal por torrent (retida N dias).
- **cluster_stat_samples** (PK `id bigint`, 00033/F2): `sampled_at`, `downloaded_total`, `uploaded_total`. Rollup do throughput ACUMULADO do cluster — 1 linha por intervalo com a SOMA dos totais cumulativos de todos os torrents (inclui removidos → curva monotônica). Retenção longa (tunável `metrics.cluster_sample_retention`, 0=para sempre). Base do gráfico de evolução em Métricas (`GET /metrics/cluster-throughput`, downsampling por `date_bin`). Escrito pelo worker `internal/clusterstats`.
- **torrent_migrations** (ADR-018/031): `torrent_id`, `source_node_id`, `dest_node_id`, `status` (**QUEUED**/PENDING/COMPLETED/FAILED), `min_progress` (piso que o destino tem de comprovar no recheck — foto do progresso da origem; 1.0 = torrent completo), `token_sha256` **nullable**, `token_expires_at` **nullable**, `serve_command_id`, `pull_command_id`, `error`, timestamps, `completed_at`. **Cancelamento pelo operador (#87)** não tem estado próprio: é `FAILED` com `error = 'cancelada pelo operador'` (a API deriva `cancelled: true` do motivo) — o enum não mudou e não há `CHECK`, e muitos leitores tratam "terminal" como `COMPLETED`/`FAILED`. Índice único de "em voo" cobre `QUEUED` **e** `PENDING` (um torrent não pode ter duas migrações disputando-o). O token só é emitido na **promoção** QUEUED→PENDING: gerá-lo na entrada da fila faria seu TTL correr durante a espera.

## Trackers (ADR-019/020)

- **trackers**: `user_id`, `name`, `announce text` (**segredo, nunca exposto na API**), `host` (só exibição), `is_default bool`, timestamps, `deleted_at`, `source text` (etiqueta do .torrent, ex.: SAMARITANO), `api_url text`, `api_token text` (**segredo**, integração UNIT3D), `image_host_key text` (**segredo**, #193 / ADR-040, migration 00045: chave do operador para o host de imagem próprio do tracker), `image_host_key_host text` (#193 / ADR-040: o host DNS para o qual a chave foi cadastrada — se o `upload_url` do perfil mudar de host, a chave antiga não serve mais). Nome único por operador entre vivos; ≤1 default por operador.
- **tracker_profiles** (ADR-037, 00043): o perfil do **site** de um tracker — camada 2, exportável, **sem coluna de credencial** (a camada 3, `api_token`/`announce`, fica em `trackers` e nunca é exportada). `tracker_id` (FK trackers; **um perfil vivo por tracker**, único parcial `WHERE deleted_at IS NULL`), `family text` (default `unit3d`, validada em Go), `schema_version int` (≥ 1; versão do **formato** do perfil, o que o export da #197 carimba — a versão que o código emite — e o import confere), `taxonomy jsonb` (sempre objeto, `CHECK`), `created_at`, `updated_at`, `deleted_at`. `taxonomy` é o **documento** do perfil — apesar do nome histórico da coluna: os eixos na raiz, `{"category"|"type"|"resolution": [{"id", "name", "kind"?, "origin"}]}`, e uma chave reservada por seção ao lado deles. A seção `description` (#192, **sem migration e sem coluna nova**) é a chave `"description": {"media_blocks": […], "game_blocks": […], "media_info_tag": "mediainfo"}` — a composição da descrição do upload (quais blocos, em que ordem, qual tag envolve o MediaInfo); ausente = o default, e a linha anterior à #192 é, byte a byte, um documento sem a seção. A seção `image_host` (#193, ADR-040, **sem migration e sem coluna nova**) é a chave `"image_host": {"name", "upload_url", "file_field", "auth_header", "auth_prefix", "url_path", "thumbnail_path"?}` — a Spec de forma fechada do host de imagem próprio do tracker para a cadeia de upload dos screenshots; ausente = sem host próprio (só o imgbb global na cadeia), e a linha anterior à #193 é, byte a byte, um documento sem a seção. Nos termos dos eixos: `origin` `seed` (migration) | `discovered` (descoberta no catálogo do site, #196) | `manual` (operador) | `imported` (arquivo de perfil, #197; sem migration — mora no JSONB) — a descoberta e o import **nunca sobrescrevem `manual`** (o import também não renomeia `discovered` sem pedido; origem desconhecida é protegida), e a origem é estado local que **não viaja** no arquivo de troca; `kind` (`movie`/`tv`/`game`, só em `category`) é o papel que o Portal usa para temporada/episódio e busca de jogo. Linha criada sob demanda; tracker sem linha = perfil vazio. Escrita serializada por `FOR UPDATE`. A 00043 semeia o perfil do samaritano já cadastrado com a taxonomia que estava cravada no Portal. JSONB (e não uma linha por termo) porque a unidade de export/validação é o documento e eixos/seções novos entram sem migration — ver `docs/12 - Database.md` §52-A.

## Comandos / Eventos / Alertas

- **commands** (fila durável, polling do Agent, ADR-014): `node_id`, `type`, `payload jsonb`, `status` (PENDING/DISPATCHED/DONE/FAILED), `result jsonb`, `error`, `retry_count` (entregas ao Agent — o Claim re-entrega DISPATCHED órfão após `commands.redispatch_after` e marca FAILED ao estourar `commands.max_attempts`, #111), `created_by`, `created_at`, `dispatched_at`, `finished_at`. `seq` (identity) é a **ordem de entrada na fila**: o Claim escolhe e devolve por ele — `created_at` empata dentro de uma transação e não serve de ordem (#28).
- **events**: `event_type_id`, `node_id`, `torrent_id`, `user_id`, `message`, `payload jsonb`, `severity`, `created_at`.
- **event_types**: `code`, `name`, `severity` (default INFO), `description`, `created_at`.
- **activities** (ADR-022, feed de orquestração — trilha SEPARADA de eventos/alertas): `kind` (admission_hold/admission_resume/scheduled/downloading/seeding), `torrent_id`, `torrent_name` (denormalizado), `node_id`, `message`, `detail jsonb` (o "porquê"), `created_at`. Append-only.
- **audit_log** (ADR-025, auditoria de ações do operador — trilha SEPARADA de eventos/activity/alertas): `actor` (username), `action` (descrição amigável PT-BR, ex.: `Alterou a configuração «Node offline após» para 120s`), `method`, `path`, `status_code`, `source_ip`, `created_at`. Append-only; gravada por middleware nas rotas protegidas mutadoras + login; handlers enriquecem `action` via `httpx.SetAuditAction`.
> **Retenção (#112):** `commands` (terminais), `events`, `activities`, `audit_log` e `sessions` expiradas são podados pelo maintenance worker conforme os tunáveis `retention.*` / `workers.maintenance_interval` (0 desliga). Amostras (`torrent_stat_samples`/`cluster_stat_samples`) já tinham poda própria. ⚠️ **Comando referenciado por `torrent_migrations` (`serve_command_id`/`pull_command_id`) nunca é podado (#213):** as FKs não têm `ON DELETE`, e um único comando assim no lote derrubava o `DELETE` inteiro — a poda de `commands` nunca tinha rodado em produção (64 comandos de migração travando 53.732). `ON DELETE SET NULL` foi descartado porque `IS NOT NULL` nessas colunas decide a limpeza de uma migração falha (`resumeSource`/`discardDestCopy`) e o `Reconcile` faz `JOIN` no pull.

- **alerts** (ADR-008): `code`, `severity` (default WARNING), `status` (default OPEN), `node_id`, `message`, `payload jsonb`, `opened_at`, `resolved_at`, timestamps. `episode_key text` (#211): identidade da condição que abriu o alerta — a rotação de IPv6, o início do silêncio de entrada, o veredito do Engine —, formatada em UTC com microssegundos; um episódio que já gerou alerta, em qualquer status, não reabre. NULL = regra sem episódio (dedup só por OPEN). `expired bool` (default false, #211): fechou por **validade** (`alerting.reachability_ttl`), não porque a condição deixou de existir.

- **roles**: `name`, `description`, `system bool`, timestamps.

- **role_permissions** (PK composta): `role_id`, `permission_id`, `created_at`.
- **user_roles** (PK composta): `user_id`, `role_id`, `created_at`.
- **sessions**: `user_id`, `session_token`, `ip_address inet`, `user_agent`, `expires_at`, `last_activity`, `created_at`.

## Configuração

- **settings** (ADR-023, tunáveis dinâmicos com hot-reload): `key` (PK, namespaced, ex.: `admission.dead_grace`), `value` (string; parse pelo tipo do catálogo), `updated_at`, `updated_by` (`env-seed` no seed de boot). KV puro — a metadata (tipo/default/descrição/limites) vive no **catálogo de código** (`internal/settings/catalog.go`), não no banco. Override do default; remover a linha = reset ao padrão. Ver `25 - Business Rules.md`.
- **node_settings** (ADR-039, #144 — override POR NODE da configuração de comportamento do Agent/Engine): `id` (UUID PK), `node_id` (FK → `nodes`, `ON DELETE CASCADE`), `key` (chave namespaced do catálogo, só as `PerNode`: `agent.heartbeat_interval`, `agent.command_poll_interval`, `agent.log_level`, `engine.*`), `value` (string; parse pelo tipo do catálogo), `created_at`, `updated_at`, `updated_by` (operador; `semeadura (env do Node)` quando vem da semeadura, §7 da ADR). `UNIQUE (node_id, key)`. Mesma lógica da `settings`: a metadata vive no catálogo em código e o valor é validado pelo **mesmo `Spec`**; remover a linha = o Node volta ao valor de cluster (a `settings`). **Sem soft delete** de propósito, como a `settings`: o histórico de quem mudou o quê (antes e depois) fica na **Auditoria** (ADR-025), não numa linha morta aqui; os Nodes são soft-deleted e o override de um Node removido simplesmente deixa de ser lido. Precedência efetiva: **override do Node > valor de cluster (`settings`/default do catálogo) > env do Node > default do código** — os dois últimos degraus são do Agent.
- **nodes (config do Agent, ADR-039)**: `agent_config_version text` (a `version` da configuração que o Agent aplicou **com sucesso**, devolvida no heartbeat; NULL = o Agent nunca reportou — anterior à ADR-039 — e **nunca** é lido como "em dia"), `agent_config_applied_at timestamptz` (quando essa versão foi reportada pela primeira vez; só muda quando a versão muda), `agent_config_seeded_at timestamptz` (o "uma vez por Node" da semeadura dos overrides a partir do `.env` que o Agent relata — depois de preenchido o Control Plane não semeia mais, nem que o operador apague o override semeado).
